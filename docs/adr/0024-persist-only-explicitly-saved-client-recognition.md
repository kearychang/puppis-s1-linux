# Persist only explicitly saved client recognition

Up to ten saved clients may persist in a versioned, user-only XDG JSON file containing a user-assigned label, client hardware address, last-observed timestamp, and the address set from the latest observation. This deliberately narrows ADR 0020's prohibition on persistent MAC addresses: persistence occurs only after an explicit save action, creates no automatic observation history or trusted identity, remains clearable per client and as a whole, and never enters logs, traffic initiation, or access control.

This decision also narrows ADR 0017's fully redacted snapshot rule for the local presentation contract only. The in-process/Tauri `ApplicationSnapshot` may carry full observed or saved client hardware addresses so the local Overview can display and manage them. That presentation snapshot is not itself a diagnostic or log artifact: raw labels and hardware addresses remain excluded from diagnostics and logs. Redacted saved-client aliases, last-observed times, last observed client addresses, and current-observation state may appear in the user-reviewed diagnostics preview. This accepts bounded local identifier retention so users can recognize returning client devices without adding privileged lease access or a database.
